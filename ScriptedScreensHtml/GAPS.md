# What does not work yet, and why

The working list. `COVERAGE.md` is the measured side (generated by
`ScriptedScreensHtml.Tests/coverage.py`, run it after a change); this file is the judgement:
for every gap, what it is, why it is missing, and what closes it. Three kinds of entry:

- **build**: not done yet, nothing in the way. The default kind.
- **approximation**: something is drawn, but not the way a browser draws it. Listed so it is
  replaced, not kept.
- **out**: decided against, with the reason. Reopen by deciding otherwise, not by finding it here.

Numbers as of 2026-09-15: CSS 336 of 491 standard properties handled; HTML 92 of 112 elements;
JS document 33 of 35, element 85 of 100, window 56 of 80, canvas 60 of 60.

Two things I omitted when writing the docs, corrected here:

- SUPPORT.md listed `replaceChildren`, `picture`/`source` and `sessionStorage` as working.
  `sessionStorage` is there; `replaceChildren` was not (added below); `picture` works only in
  the sense that its `img` renders and its `source` candidates are ignored, which is what a
  browser does when no source matches, but it never picks a source. Now listed under HTML.
- The approximations were listed in PLAN.md and SUPPORT.md but not the reasons behind them.
  They are here with reasons.

## HTML

| Element | Kind | Why / what closes it |
|---|---|---|
| `iframe`, `embed`, `object` | out | no second document, no plugins. A console page is one document. |
| `area`, `map` | build | image maps: a click on an `img` inside a `map` must hit-test the `area` shapes and fire the area's id. The click plumbing exists (`data-click`), the shape test does not. |
| `col`, `colgroup` | build | column widths and styles for a table by column. The parser keeps them (void tag); `AppendRow` ignores them. Closes by reading `col` widths before sizing cells and applying `col` background per column. |
| `datalist` | build | suggestion list for an input. The control is ScriptedScreens', which has no suggestion UI; could be drawn by the page as a list under the field on focus. |
| `picture`, `source` | approximation | the `img` inside renders, `source` candidates are ignored. Closes by choosing the first `source` whose `media` matches the design width (the `@media` evaluator exists) and using its `srcset`. `video`/`audio` `source` likewise. |
| `track` | out | subtitles on a video: the ScriptedScreens media element has no text track. |
| `noscript` | build | should be skipped entirely (scripts run). Today its content shows. One line in `Skipped`. |
| `base` | build | base URL for relative `href`/`src`. Relative URLs are not resolved at all today (fetches need absolute http(s)); resolving against `<base>` or the page's own URL would let a page reference `images/x.png`. |
| `bdo` | out | bidirectional override; the text engine is left-to-right only. See `direction` under CSS. |
| `dl`, `hgroup`, `menu`, `search`, `output`, `slot` | fine | render as plain blocks (a browser's default too); `dt`/`dd` have their indents. Counted as unhandled by the tool because nothing names them. |
| `template` | fine | skipped, as a browser does. A script cloning `template.content` does not work: see JS. |
| `select multiple`, `input type=color/date/time/file` | out | the ScriptedScreens control set has no multi-select, colour or date pickers and no file access. `type=color` could be a page-drawn swatch grid later. |
| `contenteditable` | out | no keyboard focus in a page; typing goes to ScriptedScreens' text control only. |

## CSS properties

Grouped as the tool groups them. "cosmetic" means the property exists to tune something this layer has no control over.

| Group | Kind | Why / what closes it |
|---|---|---|
| Backgrounds and borders: `background-position-x/-y`, `background-origin` | build | the longhands are parsed only through `background-position`; add the two names. `background-origin` needs the image box to start at padding or content edge: a small offset in `EmitImage`. |
| `corner-*-shape` per corner, `border-shape` | build | `corner-shape` is handled for all four corners at once; the per-corner and logical spellings need the same 1-to-4 expansion `border-radius` has. `border-shape` (a path outline) is a `P` outline: same code as `corner-shape`. |
| Masking: `mask-border-*`, `mask-clip/composite/mode/origin/position/repeat/size/type`, `clip-rule` | build, partly vector | `mask-image` gradient masks are vector item 10; an image mask (`mask-image: url()`) needs a vector mask from a texture's alpha (not asked for yet). The geometry longhands are the same offsets `background-*` uses. `clip-rule` is `fill-rule` for clip paths: pass `fr` on the CP def. |
| SVG presentation as CSS: `cx cy r rx ry x y d`, `marker-*`, `paint-order`, `vector-effect`, `shape-rendering`, `path-length` | build | the cascade already applies `fill`/`stroke`; geometry properties (`cx`, `d`...) need the same treatment in `CollectShapes`. `marker-start/mid/end` (arrowheads) need `<marker>` support: emit the marker's shapes at each vertex with the segment's angle. `vector-effect: non-scaling-stroke` is the baked-fit stroke width, already how `preserveAspectRatio="none"` strokes work; needs the flag read. |
| Animations: `animation-trigger`, `timeline-trigger-*`, `trigger-scope` | out | draft spec, no browser ships it. |
| Fonts: `font-variation-settings`, `font-palette`, `font-size-adjust`, `font-synthesis-*`, `font-variant-*`, `font-language-override` | out | the Fonts mod builds static atlases; no variable axes, no OpenType features, no colour palettes. `font-variant-numeric: tabular-nums` is the one that mattered and is faked with a monospace span. |
| Box sizing: `contain-intrinsic-*`, `column-width/height/wrap`, `frame-sizing` | build (column-width), out (contain-intrinsic) | `column-width` (auto column count from a width) is arithmetic on top of `column-count`. `contain-intrinsic-*` only matters with `content-visibility`, which is a no-op here. |
| Text: `line-break`, `hyphenate-*`, `text-justify`, `text-wrap-mode/style`, `white-space-collapse`, `text-autospace`, `text-fit` | build / out | `white-space-collapse` and `text-wrap-mode` are the new longhands of `white-space`; map them. `hyphens: auto` needs a dictionary: out. `text-justify` variants: TextMeshPro has one justification. `text-wrap: balance/pretty`: out (no line-breaking control). |
| Inline: `initial-letter`, `baseline-shift`, `alignment-baseline`, `text-box-*` | build (initial-letter) | `initial-letter` is the drop cap with a line count; the `::first-letter` machinery exists, the size from lines is `n * line-height`. The baseline ones are `vertical-align` spellings. |
| User interface: `caret-*`, `interactivity`, `interest-delay-*` | out | no caret (typing is in ScriptedScreens' control), and `interactivity`/`interest` are 2025 draft features. |
| Multi-column: `column-rule*`, `column-span`, `column-fill` | build | `column-rule` is a vertical line between the columns `column-count` already makes: one `L` per gap. `column-span: all` is an element that breaks out of the columns: rebuild the columns around it. `column-fill: auto` vs balance: the balancing is what exists. |
| Motion path: `offset-path`, `offset-distance`, `offset-rotate`, `offset-anchor`, `offset-position`, `offset` | build | position an element along a path: the emitter can sample a `P` at a distance; with an expression over `t` it animates on the client. Worth doing because it is the only way to animate along a curve. |
| Text decoration: `text-emphasis-*`, `text-decoration-inset` | build | emphasis marks are small glyphs above each character: a second label with dots; low value. |
| Filter effects: `flood-*`, `lighting-color`, `color-interpolation-filters` | out | SVG filter primitives (`<filter>`, feGaussianBlur...) are per-pixel: out with `filter: blur()`. |
| Overflow: `overflow-clip-margin`, `scroll-marker-group`, `scroll-target-group`, `scroll-axis-lock` | build (clip-margin), out (markers) | `overflow-clip-margin` is a larger clip rect. Scroll markers (carousel dots) are 2025 draft. |
| Shapes: `shape-outside`, `shape-margin`, `shape-image-threshold` | out | text flowing around a float's outline needs an inline formatting context that wraps lines around shapes; the layout engine has no inline flow at all (labels are boxes). This is the structural limit behind every "wraps beside" approximation below. |
| View transitions | out | no document navigation. |
| MathML | out | no user. |
| `overscroll-behavior-block/inline` | fine | logical spellings of a no-op. |
| `reading-flow`, `reading-order` | out | focus order for a keyboard; no keyboard. |
| `background-blend-mode`, `box-decoration-break`, `dynamic-range-limit`, `image-orientation`, `overflow-anchor`, `page`, `ruby-overhang`, `text-combine-upright`, `transform-box`, `transition-behavior`, `flex-line-count`, `grid` (shorthand) | build (`grid`, `transform-box`, `transition-behavior`), out (rest) | `grid` is the shorthand of `grid-template` plus auto flow: parse and split. `transform-box: fill-box` changes the transform origin box for svg: small. `transition-behavior: allow-discrete` lets `display` transition: the tween system could hold `display` until the tween ends. The rest are per-pixel, print or vertical-text niches. |

## CSS at-rules, selectors, functions, units

| Item | Kind | Why / what closes it |
|---|---|---|
| `@starting-style` | build | the style an element has when it first appears, so a transition can run from it. The tween system snapshots "what the scene showed"; an element that did not exist has no snapshot, so its first appearance snaps. Closes by cascading the `@starting-style` block as the "from" snapshot for a new element. Useful: fade-in on insert. |
| `@font-feature-values`, `@font-palette-values` | out | OpenType features and palettes: see fonts. |
| `@namespace` | out | XML namespaces in selectors; nobody writes them for HTML. |
| `@page`, `@view-transition` | out | print, navigation. |
| `::selection`, `::highlight`, `::spelling-error`, `::grammar-error`, `::target-text` | out | no text selection. |
| `::backdrop` | build | the dim layer behind a modal dialog: one full-page `R` under the dialog when `showModal()` opened it. Cheap and worth it. |
| `::file-selector-button`, `::picker`, `::picker-icon`, `::checkmark`, `::details-content` | build (`::details-content`), out (others) | `::details-content` styles the details' body: the body is an element already, match it. The others style browser-native widget parts; the select's arrow and checkbox's mark are drawn here and could take colours from these rules later. |
| `::part`, `::slotted`, `:host`, `:host-context`, `:has-slotted`, `:defined`, `:state` | out | web components / shadow DOM: no custom elements here. `customElements.define` is not provided; the DOM is one tree. |
| `::cue`, `:playing`, `:paused`, `:muted`, `:buffering`, `:seeking`, `:stalled`, `:volume-locked`, `:picture-in-picture` | out | media state of ScriptedScreens' media element is not readable from the page. |
| `:fullscreen`, `:popover-open`, `:autofill`, `:first`, `:left`, `:right`, `:past`, `:future`, `:active-view-transition*` | out | fullscreen, popovers (the `popover` attribute could be `:open` later), autofill, paged media, time-based media cues, view transitions. |
| `:user-invalid`, `:user-valid` | build | like `:invalid`/`:valid` but only after the user interacted: a flag set on the node at the first `change`. Small. |
| `:scope` | build | inside `querySelector` and `@scope` (done there) it is the root; as a bare selector it is `:root`. One case. |
| Functions: `sin cos tan asin acos atan atan2 pow sqrt hypot log exp abs sign mod round` | build | CSS trigonometric and exponential functions inside `calc()`: `Func` handles min/max/clamp; extend the evaluator with these. Half an hour. |
| `env()` | build | safe-area insets; return 0. |
| `light-dark()` | build | pick the first (light) value, or by `color-scheme`. |
| `hwb() lab() lch() oklab() oklch()` | build | colour spaces: conversion maths into sRGB; `color-mix(in oklch)` then becomes exact instead of sRGB. |
| `image-set()`, `cross-fade()`, `paint()`, `palette-mix()`, `ray()`, `xywh()`, `param()` | build (`image-set`, `xywh`), out (rest) | `image-set` picks a URL by resolution: take the first. `xywh()` is a `clip-path` rect form. `paint()` is the Houdini paint API: out. `ray()` belongs to motion paths. |
| 3D transform spellings: `rotate3d`, `scale3d`, `translate3d`, `scaleZ`, `translateZ`, `matrix3d` | approximation | the 2D projection of each is taken (`rotateX/Y` as foreshortening, Z ignored); a true perspective projection would need depth sorting the vector layer does not have. Listed under approximations. |
| Units: `cap`, `ic`, `Q`, `dpi`, `dpcm`, `dppx`, `Hz`, `kHz` | build (`cap`, `ic`, `Q`), out (resolution and frequency units: no media queries need them) | `Q` is a quarter millimetre; `cap`/`ic` need the font's cap height and ideographic advance: approximate as `0.7em`/`1em`. |

## JavaScript

| API | Kind | Why / what closes it |
|---|---|---|
| `fetch`, `XMLHttpRequest`, `WebSocket`, `Request`, `Response`, `Headers`, `AbortController` | out | a page has no network of its own by decision: data comes from Lua, so a console cannot become a general web client, and the game's own fetch path (used for images and scripts) is a one-shot download without headers or bodies. Reopen only with a reason. |
| `Worker`, `postMessage` | out | one script thread per page is the design; a worker would be a second Jint engine per page. |
| `Blob`, `File`, `FileReader`, `FormData` | out | no file system, no uploads. `FormData` over a form's fields could be built from the DOM if a script wants a map of values: cheap if asked. |
| `KeyboardEvent`, `PointerEvent`, `InputEvent`, `EventTarget`, `HTMLElement`, `Element`, `Node`, `Option` | build | constructors a page uses for `instanceof` checks and `new Option(text, value)`. No keyboard events are ever dispatched (no keyboard focus in a page), but the constructor should exist. `instanceof HTMLElement` should be true for shim elements. Added: see the changelog below. |
| `DOMParser`, `XMLSerializer` | build | parse a string into a detached tree: the detached shim can hold `innerHTML`; `querySelector` on a detached tree is the missing half (the shim has no selector matching off the main tree). |
| `atob`, `btoa` | build | base64: a few lines. Added. |
| `document.elementFromPoint` | build | hit-test the layout rects the surface already keeps for `getBoundingClientRect`. |
| `document.write` | out | replaced by `innerHTML` decades ago; ignored. |
| `element.replaceChildren`, `getClientRects`, `clientTop/Left`, `normalize`, `selected`, `selectedIndex`, `options`, `placeholder`, `alt`, `tabIndex` | build | small members: `replaceChildren` = clear + append; `getClientRects` = one rect; `clientTop/Left` = border widths; `selected`/`selectedIndex`/`options` for a select from its option nodes; the rest are attribute reflections. Added. |
| `compareDocumentPosition`, `requestFullscreen`, `setPointerCapture` | out | no use in a console page. |
| `template.content`, `customElements`, shadow DOM | out | web components need a second tree per element; the renderer has one tree. `template.content.cloneNode(true)` is the common idiom that fails: a page can use `innerHTML` from a string instead. |
| Keyboard: `keydown`/`keyup`/`keypress` | out | the page never has keyboard focus; typing happens in ScriptedScreens' own text control (which reports `input`/`change`). |
| Drag and drop, clipboard, `navigator.share`, geolocation, notifications, `history` navigation, `location` changes | out | no browser chrome behind the page. `history` and `location` exist as inert objects so libraries that read them do not throw. |
| `Element.animate()` beyond opacity/transform/size, `getAnimations()` | build (partly) | `animate()` runs through the keyframe runner, so it animates whatever the runner can: the tweenable properties. Colours snap (a colour is not a scalar; vector item 1 covers CSS transitions on background, `animate()` does not use it yet). `getAnimations` returns the handles the page made. |
| `requestAnimationFrame` at more than 30 a second | out | 30 is the vector mod's rebuild cap; a page cannot beat the renderer. |
| Canvas: `getImageData`, `putImageData`, `createImageData`, `createPattern`, `isPointInPath`, `globalCompositeOperation`, `filter` | out (pixels), build (`isPointInPath`) | the canvas is vector paths, not pixels: there are no pixels to read or write, and compositing modes are per-pixel. `isPointInPath` is a point-in-polygon test the recorder could answer. `createPattern` could be a repeated `IMG` later. |

## Approximations (drawn, but not as a browser draws it)

| What | Why | What closes it |
|---|---|---|
| Inline flow: text wraps beside a float, a drop cap or a list marker only as one shrinkable label; it does not flow around a shape or continue under the letter at the left margin | the layout engine (UI Toolkit) has no inline formatting context: text lives in labels, labels are flex boxes. Everything inline is built from rows of labels. | a real line breaker: measure text, break into line boxes, place runs around floats. Large; would also give `shape-outside`, `::first-line` without the vector, `initial-letter`, mixed inline sizes on one line. The right time is when a real page needs it. |
| An inline-block beside text (a small LED span) sits at the line bottom, not on the baseline; `vertical-align` on it is ignored | same: a row of boxes aligned flex-end | same, or per-item margin-top from the font metrics as a stopgap |
| `ruby`: the reading is small and raised after its base, not stacked above it | stacking needs a two-line inline box | same |
| `::first-letter` drop cap: the rest of the paragraph is one label beside the letter, all lines indented past it | same | same |
| `@container` size queries are decided against the design width, not the container's | a real container query needs the container's laid-out size and a re-cascade of its subtree after layout, which today runs once before layout | cascade in two passes: layout, then re-cascade elements whose rules have container conditions, then layout again (the grid code already re-runs on geometry change) |
| `::after` content sees counters before the element's children incremented them | generated content is created when the element is built, before its children | build `::after` after the children; move the pseudo creation to the end of `Append` |
| `border-image` with `px`/number slices reads them as thirds | the image's pixel size is unknown to the emitter (the vector mod downloads it) | vector: expose an image's natural size, or ask the vector mod to interpret `uv` slices in pixels |
| `text-decoration` colour, thickness, offset and style are drawn only under single-line labels | for a wrapped label the emitter does not know where TextMeshPro broke the lines | vector item 15 machinery (`fl` reports the first break) generalised to every line, or an underline per line from the vector side |
| `rotateX/Y` are the flat foreshortening, `perspective` ignored | no depth in the vector layer | a `G` with a 3D matrix and a depth-sorted mesh: vector work, not asked for |
| `animation-timeline` covers opacity and 2D transforms; `animation-range` ignored | the piecewise expression builder handles those properties; size/colour along a scroll would need width/height/colour expressions per element | extend the builder to `width`/`height`/`background-color` (colour through a `GL` ramp with `fat=`), and read `animation-range` as an offset on `p` |
| `word-break: break-all` estimates its wrapped height from an average glyph width | the layout engine breaks only at spaces; the vector mod breaks at the zero-width spaces the emitter inserts, but the box height must be known before | measure the text with the layout font at the box width, per character |
| `:hover` uses the page rect, not a raycast; a thing standing between the player and the console does not block it | the game's input module delivers presses only, so the cursor is polled | a raycast from the camera through the cursor against the console's collider before accepting the hover |
| `:active`/`:hover` state is lost when ScriptedScreens rebuilds the surface on a click, until the next pointer event | the surface component is recreated | keep pointer state in the static page registry keyed by page id, like remembered data |
| SVG `evenodd` inside a clipped svg | fixed in vector 0.11.23 | done |
| Controls: text size capped at about two thirds of the field height; `select` arrow, checkbox mark and range thumb are ScriptedScreens' look, not the page's `appearance` | the controls are ScriptedScreens elements | page-drawn controls (the checkbox and radio already are) for select and range when a page styles them; text input stays native (it needs the keyboard) |
| `@import` and `<link>` sheets are fetched once at load, `<script src>` runs after the inline script rather than before it | fetches are asynchronous; a browser blocks parsing on them | hold the page's first script until its external scripts have arrived (the module path already does this); the same for sheets |
| `color-mix()` mixes in sRGB whatever colour space is named | no oklab/oklch conversion yet | the colour space maths (see functions) |
| Relative URLs (`images/x.png`) are not resolved | a page has no base URL | resolve against `<base href>` or a `base` prop on the element |
